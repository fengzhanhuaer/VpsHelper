# 🔄 程序免宕机更新与 Github 鉴权配置

VpsHelper 的一个极具特色的功能是它能够**完全在自己的 Web UI 面板中进行生命周期的自我迭代（更新升级）**，无需管理员频繁 SSH 到服务器执行繁琐的命令。

## 一、理解在线热更新 (Hot Reload) 的原理

VpsHelper 没有臃肿的依赖库，所有的功能都被编译进了一个独立的二进制执行文件 (`vpshelper` / `vpshelper.exe`)。当面板触发更新时，它的底层流程如下：

1. **API 侦测版本**：后端每进入更新页面，都会调用 GitHub API 访问 `fengzhanhuaer/VpsHelper` 仓库的 `Releases` 数据，对比当前运行内核的 `VERSION` 标识。
2. **下载替换件**：若发现新版本，一旦点击更新，你的服务器会在后台进程将适配自身操 OS 与 CPU 架构的 `ELF` 包下载到临时缓存区。
3. **备份现场**：为了防止因为网络波动导致的半包下载损坏，程序会在替换前将当前正在运行的旧版执行文件原地重命名为 `xxx.bak` 的冷备份。
4. **启动接管指令**：主控进程将新的可执行文件赋予执行权限覆盖回原路径，紧接着向操作系统的 `systemd` 发送重拉起信号 (Restart Signal) 并立即让出当前占用退出。
5. **毫秒级恢复**：新版本代码在瞬间无缝挂载刚才落盘保存的所有 SQLite 数据库文件与缓存证书重启启动。这使得你在前台感觉不到“服务器关机了”，重连的时间仅取决于进程重新绑定端口的瞬间损耗！

## 二、突破 GitHub API 速率限制 (Github Auth)

在境内网络或某些频繁执行任务的节点上，GitHub API (特别是未验证的公开流量) 对同一个 IP 地址有着异常严苛的 **速率限制 (Rate Limit, 每小时 60 次请求)**。如果你遭遇了如下问题：
- **无法获取最新版本号**（一直显示请求失败或解析 403 限流错误）。
- **下载更新包途中阻断中断**。
- 或者如果你将本开源仓库进行 Fork 魔改为了**私有仓库 (Private Repo)**，未授权的请求是无法读取你私有发行包的。

此时，**GitHub 鉴权 (GitHub Auth Token)** 就显得尤为重要。

### 如何配置鉴权？
1. 访问您自己 GitHub 账户的 [Personal Access Tokens (Classic)](https://github.com/settings/tokens)。
2. 点击右上角的 **Generate new token (classic)**。
3. 起个名字（比如 `VpsHelper-Update`），如果你的仓库是公开的，可以只勾选最基础的开放权限；如果是由你的私有仓库下发版，请务必勾选 `repo` (Full control of private repositories)。
4. 点击底部生成，请**务必复制这串 `ghp_` 开头的秘钥**（由于安全机制离开页面后将再也无法明文查看）。
5. 回到 VpsHelper 的 Web 控制面板。
6. 进入 **[设置 & 账号] -> [系统高级设置]** 页面。
7. 在 **Github Token (用于更快的版本拉取与防止API限流)** 输入框内填入刚才复制的秘钥。
8. 确认保存。系统未来的每次检查更新与流式下载，都将携带您的身份指纹请求，**API 上限将立刻被解除至每小时 5000 次！**

## 三、探针的更新与应急降级逻辑

上述的热更新不仅限于主控端。主控端面版具备一项终极技能——**下发探针全局更新广播**。

当你点击了“更新所有选定的受控探针”后：
- 主节点会通过 WebSocket 长连安全隧道向这些全球各地异构的探针机器（可能是 ARM，也可能是旧型号服务器）发去指控命令。
- 受控的分支探针会依据自身的系统架构特征，自发地去拉取 Github 上对应的 Release 包，完成上述一模一样的热更替。
- **一旦某台探针在更新途中因为极端网络情况发生断联**或主板失联，探针内建的**降级备用地址 (Fallback Address)** 原理便会被激活，防止这台肉鸡自此“走丢”。
