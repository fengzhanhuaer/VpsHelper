# 🏗️ 后端架构设计及运行逻辑

VpsHelper 围绕去中心化轻量和云端强绑带作为它的设计中枢。

## 全核心轻量状态：Gin Web 及纯 SQLite3

作为一套多节点的大规模控制引擎，通常来说需要重度依赖外部 Redis 队列和 MySQL/PostgreSQL 数据仓，**VpsHelper 并未如此执行**。
- 它极尽可能地剥离外部基础设施束缚。一切关系型配给和长周期的时序监控点指标，统统打包丢入纯文件级别的 `VpsHelper.db` / `probe_data.db` 内。
- **并发机制与并发锁控制**: 由核心协程池（基于 Golang 强大的原生 `gotd`、`channel` 模型）完全吃下高密度的探针并发心跳流刷新诉求。不仅无需运维外部数据库缓存节点，更使其能够被一键式打包扔入极低规格 1Core512MB RAM 的袖珍海外物理鸡/轻量云服务器内流转自如。

## 防腐层扩展组件
由于 SQLite 本机的致命硬伤是：倘若其所在的独立沙盒主机直接硬盘暴毙或被云厂商锁闭机房没收，历史所有的心血指标配置（包括 TG Userbot 会话文件）都将付之一炬或被动销账。

借助于我们的云端强联动手段，该部分致命弱点已被解决：

1. **热备分形 Cloudflare D1 Serverless**：VpsHelper 完全有能力周期利用您提供的边缘 Worker API 路由。系统会将本体的 `SQL` 列通过流式切割片传输。将 SQLite 完全异构对等到 D1 网络上。使得即便机器报废瘫痪，仅需在一个全新的系统起新进程重新 "云端下拉"，几分钟内所有监控恢复往昔！
2. 将 **Let's Encrypt 证书验证** 以及一系列需要对域名执行公网 ACME 80 端口 HTTP 的认证协议转为了 **DNS-01 验证**，免遭无公网 80（端口未开）被限制的环境影响。
