# VpsHelper: 探针 TLS 加密与 D1 数据库管理进阶指南

## 一、探针节点自动 TLS 通讯加密 (DNS-01 验证)

在早前的版本中，探针 (Probe) 与主控端之间的 WebSocket 隧道通常为明文 `ws://`，或者依赖反向代理处理外层 HTTPS。最新版本现已原生支持基于 **Let's Encrypt DNS-01** 的高安全性全自动证书申请和续订方案。

### 核心优势
- **无需开放 80 / 443 端口**：完全依靠 Cloudflare API 自动推拉 TXT 记录完成 ACME 身份验证。
- **无视 CDN 层状态**：哪怕该子域名处于 "灰云" (DNS Only) 未开启 Cloudflare Proxy，依旧能够顺利获批全球公网受信任的 SSL 证书。
- **探针底层的严格身份核验**：一旦成功签发 TLS 证书，主控端将强制向所有探针下发 `wss://` 连接指令。探针核心启动后会执行严格的 TLS 握手验证机制（拒绝虚假重定向和过期证书），确保通讯彻底防篡改。

### 如何启用？
1. 在 **Cloudflare 管理** 页面，配置具备对目标域名（Zone ID 自动嗅探）具备编辑 `DNS` 及 `Zone` 权限的全局 **Cloudflare API Token**。
2. 进入主控端的 **探针节点管理** 底部的通讯设置区域。
3. 填入你预先配置好解析的子域名，并勾选 **🔒 自动申请 TLS 证书 (Let's Encrypt DNS-01)**。
4. 点击保存。系统将于后台向 Let's Encrypt 发起自动化 DNS 认证并在成功后进行 15 周年的证书热流化落库。
5. **刷新页面**：你会看到全新的四态状态指示器（⏳申请中 / 🔒健康有效 / 🟡临期预警 / 🔴过期 / ❌失败回退说明），并在确保证书准备完毕后平滑升维探针的通讯通道。

## 二、Cloudflare D1 边缘灾备与全量覆写策略

VpsHelper 的所有核心设置与监控记录均默认安全保存在本地的 SQLite 中。为解决机器可能失联或销毁的风险，系统内置了直接与 Cloudflare D1 Serverless Database 相连的异地热备功能。

### 新特性：⚠️ 全量覆写操作
随着系统的不断迭代更新，本地的 SQLite 表结构可能会不断自动迁入新的业务字段（如 `report_interval`、`tg_user_id` 等）。这可能导致常规覆盖式同步遭遇 `SQLITE_ERROR: table has no column named XX` 等架构失调错误。

因此在 **数据库管理** 面板中，我们增加了具备防御提示的 **全量覆写 D1（用本地覆盖云端）** 按钮。

#### 覆写底层机制：
1. **二次防护对话框**：防止由误触导致对 Cloudflare D1 云端结构毁灭性的清空。
2. **Schema 级强同步拦截 (`DROP`然后`CREATE`)**：在执行数据同步前，一旦检测到两端字段结构产生分歧，工具侧将自动拉取本地最新的 SQLite `PRAGMA` 制表语句，通过 `DROP TABLE IF EXISTS` 迅速推翻云端旧表并热重建，实现完全兼容的数据仓更新。
3. 行级进度切片与前端 SSE (Server-Sent Events) 流式无阻断渲染，海量级多表日志的动态上浮汇报。
